# 작품 관리와 배포

- 저장소의 `works-data.js`는 공개/비공개 작품을 모두 보관하는 편집 원본입니다.
- 관리자 페이지에서 로컬 저장소를 연결해 등록/수정한 뒤 Commit + Push합니다.
- Vercel은 `node build-public.cjs`를 실행해 `dist` 폴더만 배포합니다.
- 배포본에는 공개 작품과 해당 이미지, 사이트 화면에 필요한 파일만 포함됩니다.
- 비공개 작품 전용 이미지, 사용하지 않는 이미지, 백업 폴더는 배포하지 않습니다.
- 공개 작품과 같은 이미지 파일을 공유하면 그 이미지는 공개됩니다.
- 로컬에서 공개 배포본을 확인하려면 `node build-public.cjs` 실행 후 `dist`를 정적 서버로 엽니다.

## 비공개 범위

이 설정은 새 웹 배포본에서 자료를 제외합니다. 원본 Git 저장소, Git 이력, 과거 배포본이나 이미 내려받은 파일을 지우지는 않습니다. 민감한 자료를 보관한다면 GitHub 저장소의 접근 권한과 과거 배포 접근도 따로 관리해야 합니다. 비공개 전환은 Commit + Push 후 새 배포가 완료되어야 운영 사이트에 반영됩니다.

## 등록 동작

저장이 완료되면 새 등록 폼으로 돌아가며, 방금 사용한 도구는 유지합니다. 관리자 목록은 등록순, 제작일순(각 최신/오래된), 작업명순을 선택할 수 있습니다. 중요 작업은 관리자 목록 상단에 고정하지 않고 별도 중요 작업 목록에서 관리합니다. 기존 자료에는 등록 시각이 없어 등록순은 원본 배열 순서를 사용합니다. 새 등록은 맨 앞에 추가됩니다. 메인/아카이브의 중요 작업 우선 표시는 그대로입니다.

작업을 체크한 뒤 제작일 변경을 누르면 선택한 작업의 시작일/종료일을 일괄 변경할 수 있습니다. 선택하지 않은 날짜는 유지되며 종료일은 삭제할 수도 있습니다. 아카이브와 상세 화면의 사용 도구는 일반 도구, AI 도구 순으로 표시하며 각 그룹 안에서는 알파벳순으로 정렬합니다.

긴 상세 이미지는 폭 1600px, 일반 이미지는 가로/세로 1920px 이내로 최적화합니다. 이미 축소해 저장한 이미지는 원본을 다시 올려야 화질이 복구됩니다.

## 작업 유형과 자유 태그

`tags` 배열 하나에 작업 유형을 첫 번째로, 자유 태그를 입력 순서로 저장합니다. 예: `["개인 프로젝트", "반응형", "뷰티"]`. 기존 레코드는 태그가 없어도 조회·수정할 수 있습니다. 기존 작업 유형을 자동 지정하지 않습니다. 별도의 DB 마이그레이션은 없습니다(현재 Supabase 미사용).

- 등록/수정 폼의 태그에서 작업 유형 하나를 선택하고 자유 태그를 쉼표 또는 Enter로 추가합니다. 신규 등록은 작업 유형이 필수입니다. 추천 태그와 사용 중인 태그 자동완성을 사용할 수 있습니다.
- 목록의 유형 필터에서 미설정 작업을 찾습니다. 헤더 체크박스는 현재 페이지만 선택합니다. `검색·필터 결과 전체 선택`은 페이지 밖의 결과도 선택하며 기존 선택을 해당 결과로 교체합니다. 선택 해제는 전체 선택을 지웁니다.
- `유형·태그 변경`에서 유형 변경과 자유 태그 추가/제거를 입력하고 미리보기를 확인한 다음 적용합니다. 제거와 추가에 같은 태그를 입력하면 제거가 우선합니다. 다른 필드는 유지합니다.
- 파일 전체를 한 번에 저장하므로 일부 프로젝트만 성공하는 상태는 만들지 않습니다. 쓰기 실패 시 대상과 원인을 표시하고 기존 메모리 상태를 유지합니다.
- 수정한 작업이 현재 편집 중이라면 편집 폼의 태그도 갱신합니다. 저장 후 GitHub Desktop에서 Commit → Push해야 공개 사이트에 반영됩니다.
- 공개 카드에는 카테고리 다음에 유형만 표시합니다. 상세 팝업의 TAGS에는 유형과 자유 태그가 모두 표시됩니다.

검증: `node tests/tags.cjs`, `node build-public.cjs`. 브라우저 테스트는 Playwright 설치 후 로컬 서버(8765 포트)에서 `node tests/ui.cjs`로 실행할 수 있습니다. 테스트는 가상 폴더를 사용하므로 원본 작품 파일을 수정하지 않습니다.
